# Validation / review notes

Current local-primary public example (2026-09-10, AUTO-idle update):

- `local_primary_hvac_action_aux_heating_example.yaml`: focused neutral public controller
- Automations in the focused public example: 6
- Automation IDs: 6 distinct IDs
- Bare `| float` filters without an explicit default: 0
- `local_primary_helpers_example.yaml`: matching neutral helper example
- Device-target-to-desired-helper back-synchronization is intentionally absent
- Native AUTO remains native AUTO; the established AUTO target-correction curve is unchanged
- `AUTO + idle` is no longer a blanket auxiliary-heating block
- `idle` is treated as neutral permission only; external demand conditions must still be satisfied
- `AUTO + cooling` and unclear/None AUTO action remain hard blocks for auxiliary heating
- The 25-minute auxiliary release can continue through `heating -> idle` when the external-demand template remains true
- The 25-minute `for:` still intentionally restarts after a Home Assistant restart/reload (fail-safe delay)
- AC-active auxiliary-radiator logic and AC-OFF winter-reserve logic remain mutually exclusive by main climate state
- Daytime and nighttime AC-OFF winter reserve now require a valid outdoor temperature <=20 °C
- The fuller production design additionally documents a separate switch-controlled heater with the same AUTO-idle interpretation and an absolute UNIX-timestamp manual deadline stored in `input_datetime`

Latest field observation documented in the repository:

- During one AUTO cycle, the unit remained `idle` while the external room temperature was above desired.
- Without a forced HVAC-mode change, the same unit later transitioned to `cooling` while remaining in native AUTO.
- Because of that, no stronger AUTO offset curve and no forced AUTO->COOL/HEAT fallback has been added yet.
- Repeated real-world cycles should be observed before changing the AUTO curve.

Security/privacy review of the local public example:

- generic entity IDs only
- no personal room/entity names from the source installation
- no local IP addresses
- no e-mail addresses
- no MAC addresses
- no passwords
- no API keys / bearer tokens / webhook IDs
- no private hostnames

The public YAML is an example and should still be checked with the target Home Assistant installation after replacing placeholder entities, because available modes, services and device behavior can vary by integration and firmware.
